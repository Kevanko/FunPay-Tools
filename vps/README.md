# FP Tools — VPS

VPS держит аккаунты онлайн через отдельные прокси, собирает баланс и непрочитанные сообщения, отправляет приветствия и ответы по ключевым словам. Автовыдача, отзывы, бонусы и события заказов остаются в расширении: для них нужен работающий браузер.

## Установка

Выберите проверенный полный commit SHA релиза. Загрузите и изучите установщик перед запуском:

```bash
curl -fsSL "https://raw.githubusercontent.com/Kevanko/FunPay-Tools/$FPT_REF/vps/install.sh" -o install.sh
sudo FPT_REF="$FPT_REF" bash install.sh
```

`FPT_REF` обязателен и должен содержать 40 шестнадцатеричных символов. Установщик загружает все исходники и lockfile из одного commit, проверяет SHA256 архива Node и выполняет `npm ci`. Он использует отдельного пользователя `fptvps` и локальный Node, не меняет firewall или чужой reverse proxy.

Сервис по умолчанию слушает только `127.0.0.1:8787`. Подключайтесь через SSH-туннель либо свой HTTPS reverse proxy. Публичный HTTP запрещён расширением и сервером. Пример локального туннеля:

```bash
ssh -N -L 8787:127.0.0.1:8787 user@server
```

В расширении укажите `http://127.0.0.1:8787`. Для прямого HTTPS задайте `FPT_HOST` и `FPT_CERT_DIR`, содержащий `fullchain.pem` и `privkey.pem`. Без действительного сертификата публичный listener не запускается.

## Управление

```bash
systemctl status fpt-vps
systemctl restart fpt-vps
journalctl -u fpt-vps -f
```

Токен и ключи аккаунтов хранятся в `/opt/fpt-vps/data.json` с правами 0600. Не публикуйте этот файл или ключи. API принимает токен только в `Authorization: Bearer <token>`; параметры URL с токеном не поддерживаются.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Проверка доступности и capabilities, без токена |
| GET | `/stats` | Онлайн, баланс и непрочитанные сообщения |
| GET | `/accounts` | Аккаунты без golden_key |
| POST | `/accounts` | Добавить или обновить аккаунт и текстовые автоответы |
| DELETE | `/accounts?id=` | Удалить аккаунт |
| GET | `/log` | Последние события |

Неопределённая отправка сохраняется в `arState.pending`. Сервис проверяет историю чата; если подтверждения нет, автоматический повтор блокируется. Перед ручным сбросом pending убедитесь, что сообщение не было доставлено. Это предотвращает повторную отправку после потери ответа сервера.
